# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

## Реализация

- `POST /api/triage` валидирует JSON: пустой, отсутствующий или нестроковый `text`, а также битый JSON получают HTTP 400 и `{"status":"invalid_input"}`.
- Ожидание модели ограничено 300 мс: `AbortController` передаётся имитатору, а `Promise.race` страхует случай, когда модель игнорирует отмену.
- При корректном ответе модели возвращается HTTP 200 и `{"status":"ready","topic":"delivery|pricing|other","draft":"…"}`. Черновик обрезается по краям, пустой черновик и чужая тема считаются сбоем.
- При таймауте, ошибке модели и ответах `[bad-json]`, `[bad-topic]`, `[empty-draft]` возвращается HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. `mock-ai.mjs` не изменялся.
- Страница показывает тему и черновик при успехе. На `manual_review`, пустом вводе и сетевой ошибке показывает сообщение менеджеру и очищает предыдущий черновик (в том числе сразу при отправке новой заявки), чтобы старый текст нельзя было отправить клиенту по ошибке.

## Тесты

Зависимостей нет, используется встроенный тест-раннер Node.js 20:

```sh
node --test test/triage.test.mjs
```

Если в системе несколько версий Node.js, переключитесь на 20-ю (`nvm use 20`), как указано в разделе «Запуск».

Тест сам поднимает сервер на свободном порту и проверяет:

- пустой, отсутствующий, нестроковый и битый ввод (HTTP 400, `invalid_input`);
- успешный разбор и определение темы;
- все сбои имитатора: `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` (HTTP 200, `manual_review`, `topic` и `draft` равны `null`);
- что таймаут срабатывает быстро и что зависшая модель не блокирует ответ дольше 300 мс;
- что страница по `GET /` отдаётся и содержит блок черновика.

## Польза для менеджера

Менеджер получает готовый черновик ответа за доли секунды, но при любом сбое AI страница честно переключает его в ручной разбор и убирает старый черновик, поэтому клиенту не уйдёт устаревший или выдуманный текст. Эффект можно измерить долей заявок с готовым черновиком, средним временем первого ответа клиенту и числом правок черновика перед отправкой.
